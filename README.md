# ECE 444 — Antennas, Phased Arrays, and Radar Systems

Course site for ECE 444 (USAFA, Fall 2026). A Jupyter Book under `book/`, with
reveal.js decks, interactive widgets, and LaTeX practice sets served alongside
it. Every push to `main` rebuilds and publishes to GitHub Pages.

This file is the mechanical how-to: edit a thing, rebuild it, look at it.
Conventions and the traps that ship silently wrong live in
[`CLAUDE.md`](CLAUDE.md); the course-wide content contract is
[`COURSE_SPEC.md`](COURSE_SPEC.md).

## Layout

| Path | What |
| :-- | :-- |
| `book/moduleNN/<slug>/index.md` | the lesson page (MyST markdown) |
| `book/extras/slides/<slug>.md` | the reveal.js deck — the file you edit |
| `book/extras/slides/<slug>.html` | generated wrapper; loads the `.md` at runtime |
| `book/extras/slides/fig/*.svg` | deck figures, inlined at load by `deck-tools.js` |
| `book/extras/viz/*.html` | interactive widgets, iframed from lesson pages |
| `book/extras/viz/img/*.svg` | lesson-page figures |
| `book/extras/practice/*.pdf` | built practice PDFs — **committed**; what the site serves |
| `book/extras/labs/*.pdf` | built lab packets (blank copies only) |
| `book/extras/handouts/*` | printable reference sheets (Smith charts) |
| `latex/` | practice and lab sources, and their build scripts |
| `latex/fonts/Barlow/` | the body font, vendored (SIL OFL) — loaded by path, no install |
| `scripts/` | deck wrapper generator, lesson scaffolder, figure generators |
| `scripts/verify/` | headless-chromium render checks — see its own README |

Anything under `book/extras/` is copied to the **site root**, so
`extras/slides/x.html` is served at `/slides/x.html` and a lesson page reaches
it as `../../slides/x.html`. Don't leave stray files there; they get published.

## Setup, once per machine

```sh
pip install -r requirements.txt
```

That is enough to build and view the book. LaTeX and the render harness are
only needed for the things that use them — see those sections.

## Edit a lesson page

Edit `book/moduleNN/<slug>/index.md`, then:

```sh
jupyter-book build book/ --all
python -m http.server -d book/_build/html 8000   # then open localhost:8000
```

**Always `--all`.** A change touching only `book/extras/**` leaves Sphinx with
no out-of-date target: it prints "no targets are out of date", skips copying
extra files, and serves you the *previous* deck or widget. This is the single
most common way to spend twenty minutes debugging an edit that was never built.
(CI gets away without it because a fresh checkout has no `_build` to skip.)

Serve over HTTP rather than opening `file://`. Decks fetch their markdown with
XHR and widgets load in iframes; both are blocked on `file://`.

## Edit a deck

Edit `book/extras/slides/<slug>.md`. **You do not regenerate the `.html`** —
the wrapper is a thin shell that fetches the markdown at runtime, so a deck
edit needs only the book rebuild above.

Slide separators, as configured in the wrapper:

- `---` on its own line — new slide
- `--` on its own line — new *vertical* slide
- `Note:` at the start of a line — speaker notes for that slide

Regenerate the wrapper only when you create a deck or change its title:

```sh
python scripts/make_deck_html.py \
  --slug L04-impedance-feeding-baluns \
  --title "L4 - Impedance, Feeding, and Baluns"
```

The deck markdown goes through `marked`, which mangles LaTeX in four specific
ways MyST does not — so the *same equation* can render on the lesson page and
break on the slide. The four are listed under "Gotchas" in `CLAUDE.md`. Check
the deck itself, not the lesson page.

## Regenerate a figure

Data plots are generated by committed scripts, never hand-drawn:

```sh
python scripts/graphics/l04_lmatch_smith.py
```

Each writes native inline SVG to both `book/extras/slides/fig/` (deck copy, no
equations — the math goes in the slide text so it inherits the deck font) and
`book/extras/viz/img/` (lesson-page copy, formulas allowed). Rebuild the book
afterward with `--all`.

Regenerated SVGs and PDFs always show up in `git status` even when nothing
changed — an embedded timestamp and a random element id differ every run. A
dirty file after a rebuild is not evidence you changed anything; check the
diff.

## Rebuild a practice set

Practice PDFs are **committed** — CI never runs LaTeX, so the file in
`book/extras/practice/` is literally what students download. They need the
private [`livethisdream/latex-tools`](https://github.com/livethisdream/latex-tools)
repo for the house macros:

```sh
git clone --depth 1 https://github.com/livethisdream/latex-tools /workspace/latex-tools
TEXINPUTS=/workspace/latex-tools/tex/latex//: bash latex/build_practice.sh 06
```

That builds `ECE444_L06_Practice_{blank,SOLUTIONS}.pdf` and copies both to
`book/extras/practice/`. Commit them.

The scripts run **lualatex, not pdflatex** — the body font is Barlow, loaded as
OpenType through `fontspec` (see `latex/ece444_fonts.tex`). If lualatex dies
with `module 'luaotfload-main' not found`, that is a missing `texlive-luatex`
apt package, not a font problem. Math stays in Computer Modern deliberately;
the reasoning is in the header comment of `ece444_fonts.tex`.

Never commit a PDF built with stand-in macros. Reimplementing the macros well
enough to compile is easy and useful for syntax-checking the source; measured
against the real thing it diverges by 2-4% of pixels, accumulating into visibly
different vertical placement down the page. Real macros or no PDF.

## Rebuild a lab packet

Same toolchain, different script. Labs are standalone documents (no shared
harness), and only the **blank** copy is published — the KEY is a graded
deliverable, so `latex/.gitignore` keeps all `latex/*.pdf` out of git:

```sh
TEXINPUTS=/workspace/latex-tools/tex/latex//: bash latex/build_lab.sh L04_Matching
```

Photographs live in `latex/figures/` and are detected with `\IfFileExists`, so
the packet compiles either way — with the photos if present, with labelled
placeholder boxes if not. Size them with `width=`, never `scale=`: `scale=` is
tied to the pixel dimensions of whatever image was there when you tuned it, and
a replacement silently runs off the margin. Store photos at print resolution
(~200 dpi for the size they actually print) — the originals are embedded in a
PDF the site serves.

## Add a lesson

Don't hand-edit `book/_toc.yml`. It is regenerated wholesale from the `LESSONS`
manifest (and `LABS`, for lab sub-pages) in the scaffolder:

```sh
python scripts/scaffold_lessons.py --dry-run   # see what it would do
python scripts/scaffold_lessons.py             # create missing shells + toc
```

It writes only what is missing — existing lesson pages and decks are left
untouched unless you pass `--force`.

## Verify before you commit

A page that builds is not a page that renders. Every defect this course has
shipped past the build — raw `$$` on a slide, a clipped widget, an iframe
pointing at nothing — was found by rendering it in headless chromium.

```sh
cd scripts/verify && npm install     # once per container: vendors reveal.js + mathjax
scripts/verify/mech_check.sh 04 impedance-feeding-baluns
```

See [`scripts/verify/README.md`](scripts/verify/README.md) for the individual
checkers and what each one covers. The CDNs are blocked in the course
containers, which is why the harness vendors reveal.js and MathJax locally —
without `npm install` the checkers stop rather than quietly passing a deck that
never loaded its math.

## Publish

Push to `main`. `.github/workflows/deploy.yml` builds the book and force-pushes
the result to `gh-pages`. Nothing else is needed — and nothing else is run: CI
does not execute LaTeX, Python figure scripts, or the scaffolder, so any
artifact those produce has to be committed.
